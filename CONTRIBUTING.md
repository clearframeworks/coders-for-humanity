# Contributing

Start with the public problem, not a preferred technology. Check existing projects and issues before opening another effort. Research, design, translation, documentation, testing, field review, and domain expertise are first-class contributions.

Choose a task with a clear objective and acceptance criteria. Discuss changes in scope with its maintainer. For code, make a focused branch, explain the resulting behavior in a pull request, and include relevant test results. Do not include secrets, private datasets, or unapproved dependencies. AI-assisted contributions have the same understanding, attribution, security, and review requirements as other work.

Run the checks listed in README.md. Test keyboard access and both appearance modes when changing UI. Tests should establish behavior or a meaningful security boundary, not merely repeat implementation details.

Before review, update relevant documentation and describe limitations. A maintainer reviews scope, functionality, accessibility, privacy, licensing, and operating consequences. Do not self-approve sensitive changes. Security reports use the private process in SECURITY.md.

Source contributions are accepted under the repository's MIT license. Data, documentation imported from elsewhere, research, and visual assets need their own provenance and compatible permissions. Contribution grants no special ownership of the official institution.
